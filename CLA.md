The Project distributes its first-party code under the MIT Licence (SPDX identifier `MIT`). The
MIT licence text asserts `Copyright (c) 2026 RetailTwin AI Contributors`. That assertion requires

This agreement is that authorisation. It is an **inbound** agreement: it covers contributions
already present in the Project's history as well as contributions made after adoption, so that the
licence grant is complete for the whole of the Project's first-party code.

## 4. How acceptance is given

Acceptance is given in either of the following forms. Both are recorded in the Project's
repository, so an acceptance is always attributable to a specific source.

### 4.1 Signature in the acceptance register

You append a signature line to the register at [§5](#5-acceptance-register), naming your GitHub
account, your preferred display name, the date, and the source of the acceptance. The register is
then updated through a pull request against this file.

### 4.2 Written confirmation in a Project issue

You post a written confirmation in the acceptance-request issue opened for You by the Project
owner. A public issue comment, made under the GitHub account that authored the Contributions, is
an in-repository written confirmation and requires no separate signature.

The confirmation must state, in substance, that your contributions to the Project are licensed
under the MIT Licence and that you accept this agreement. The exact text requested is given in the
acceptance-request issue.

### 4.3 Attribution

Each acceptance is attributed to its actual source — a commit SHA that added a signature line, or
the permalink of the issue comment that carried the confirmation. No acceptance is inferred from
the fact that a Contribution was merged, from `push` access to the repository, or from any other
circumstance.
